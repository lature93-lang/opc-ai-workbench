# 需求说明

客户经理填写，交回总助。总助把全文呈交 17，用于确认点「需求定义」。通过用语是「确认需求」。

## 填写说明

文稿开头写三行：项目、日期、填写人。填写人使用角色名。

| 字段 | 怎么写 |
| --- | --- |
| 背景 | 三到五句，写清现状和这次要处理它的原因。 |
| 目标 | 写完成后 17 能指着结果说「这件成了」的那一句，加上可观察的结果。 |
| 用户/场景 | 每个角色一段：谁，在什么情况下，完成什么。只写这次要服务的人。 |
| 约束 | 写必须遵守的边界，例如不做的功能、文案限制、运行环境。 |
| 验收标准 | 每条都能被质检员单独判定。默认每条都是必过项。 |
| 未决问题 | 写还会挡住下一步的问题，并注明对应的待拍板文件。没有则写「无」。 |

未决问题一旦会改变目标或验收标准，先走待拍板，得到结论后再把结论写回本页。

## 短示例

项目：内部读书会。日期：2026-10-29。填写人：客户经理。

- 背景：报名靠口头统计，周五现场对人数对不上。17 要求改成一个内网页面。
- 目标：同事能在周五中午前自己报名，页面显示已报人数和剩余名额。
- 用户/场景：同事打开内网页面，填写称呼并报名。组织者打开同一页面查看人数。
- 约束：不做账号体系，不做支付。称呼由填写人自己输入。
- 验收标准：能提交一条报名；已报人数加一；名额到 12 人后不能再提交。
- 未决问题：无。名额上限 12 人已由 17 在 2026-10-29 确认，见当次待拍板。

### 背景

用三到五句写清现状，以及 17 为什么现在要做。

### 目标

写一件可观察的完成状态。

### 用户/场景

按角色分段，每段包含谁、场合、要完成的事。

### 约束

列出必须遵守的边界和明确不做的事。

### 验收标准

1. 一条可单独判定的标准。
2. 下一条标准。

### 未决问题
