# 任务

一张任务只做一件可交付的事。开发实现使用本模板，负责角色写「开发者」。其他角色若要拆出独立交付，也用本模板，并写明自己的角色。

## 填写说明

文稿开头写三行：项目、日期、填写人。

| 字段 | 怎么写 |
| --- | --- |
| 目标 | 一句完成状态，能对应方案里的一条任务拆分。 |
| 输入 | 列出已确认的需求说明、方案、仓库地址或本地目录、上游任务的产出。 |
| 产出 | 列出交回总助时要有的文件、PR 链接或可运行结果。 |
| 验收标准 | 写质检时怎么判断这一张任务做完，尽量对应需求里的某一条验收标准。 |
| 优先级 | 只写高、中、低。挡住演示的写高。 |
| 负责角色 | 只写：总助、客户经理、产品经理、开发者、质检员、逆向工程师。 |

GitHub 上的开发任务在产出里写「PR 链接」。本地 Codex 任务在产出里写「17 已批准的命令结果摘要」。

## 短示例

项目：内部读书会。日期：2026-10-29。填写人：产品经理。

- 目标：报名页可以提交称呼，并在满 12 人后禁止提交。
- 输入：已确认的需求说明和方案。仓库为 17 指定的内网项目仓库。
- 产出：云端开发 agent 打开的 PR 链接，包含报名页和创建报名的接口。
- 验收标准：提交一条称呼后人数加一；第 13 次提交被拒绝并显示「名额已满」。
- 优先级：高。
- 负责角色：开发者。

## 正文

- 项目：
- 日期：
- 填写人：

### 目标

一句完成状态。

### 输入

列出本任务依赖的文档、仓库或目录。

### 产出

列出交回总助的具体结果。

### 验收标准

写可单独检查的判定。

### 优先级

高、中或低。

### 负责角色

六个角色之一。
