# 连接与授权

密钥、客户端机密和访问材料都经加密输入框提供，存为环境变量。本页不记录变量名的值。步骤里需要替换的位置用文字说明，替换后的整段地址和返回内容不写入仓库。

微信桥与滴答清单的 OAuth 已接通。日常先做验证。验证失败再按各节的「失效重连」处理。

DeepSeek Harness 已弃用，本工作台不再接入。

官方滴答接口以 Dida365 Open API 为准，文档入口为 <https://developer.dida365.com/docs#/openapi>。

## Notion

### 前提

17 有可写入的 Notion 工作区。已经有的数据库是「项目总台账」，字段见 [日程](schedule.md)。数据库「项目事项」和它的三个视图是目标结构，要先按日程文档的补齐步骤建好。下面的步骤在补齐完成之后执行。补齐完成前，不把「项目事项」当成已经存在的库。Grok Bot 使用的 Notion 连接已能代表 17 调用该工作区，或 17 准备好把集成邀请到相关数据库。

### 步骤

1. 17 经加密输入框提供 Notion 集成凭证，存为环境变量。总助不在对话里复述该值。
2. 在 Notion 中把该集成邀请到「项目事项」所在页面，使它能读和写这个数据库。
3. 对照 [日程](schedule.md) 的字段表检查属性类型。缺少的属性由总助列成清单，17 同意后补齐。已经存在的属性不擅自改类型。
4. 确认三个视图存在：看板、日历、待我决定。筛选条件与日程文档相同。
5. 做一次下面的验证。

### 权限范围

只读写「项目事项」数据库以及它为了显示所必须的父页面。17 当次消息里给出的页面链接可以读取。其余页面不读取、不修改。

### 如何验证已连上

1. 总助写入一条事项：项目选一个测试用选项，事项写「连接自检」，类型为提醒，状态为待办，待我决定不勾选，来源为总助，截止留空。
2. 17 在看板的待办列能看到「连接自检」。
3. 总助把该行状态改为已取消。
4. 17 在已取消列能看到它。两边都一致，即视为已连上。

### 失效重连

调用返回未授权时，17 重新经加密输入框提供凭证，存为环境变量，并确认集成仍被邀请在该数据库上。然后重做验证。旧值停止使用。

## 滴答清单 OAuth

### 前提

17 有滴答清单账号。清单「17项目日程」已存在，或允许在验证时确认它的名称。使用 Dida365 官方 Open API 的 OAuth。授权已经接通的，先做验证。

### 步骤

1. 在滴答开发者中心登记或复用已有应用。回调地址只用 17 已经登记的那一个。
2. 客户端标识和客户端机密经加密输入框提供，存为环境变量。
3. 请 17 在浏览器打开授权页并同意。授权页地址为 `https://dida365.com/oauth/authorize`。查询参数包括：`client_id`（客户端标识）、`scope`（`tasks:read` 与 `tasks:write`，中间用空格）、`state`（当次随机串）、`redirect_uri`（已登记回调）、`response_type`（固定为 `code`）。
4. 17 同意后，回调里带回授权码。总助用该授权码向 `https://dida365.com/oauth/token` 换取访问材料。请求使用 Basic 认证，用户名是客户端标识，口令是客户端机密。表单字段为：`code`（授权码）、`grant_type`（固定为 `authorization_code`）、`scope`（与授权页相同）、`redirect_uri`（已登记回调）。返回的访问材料只写入环境变量。
5. 调用 `GET https://api.dida365.com/open/v1/project`，在返回的清单里找到名称「17项目日程」，把清单 ID 记在总助运行备忘，不写入仓库。
6. 做一次验证。提醒的创建使用 `POST https://api.dida365.com/open/v1/task`，完成使用 `POST https://api.dida365.com/open/v1/project/{projectId}/task/{taskId}/complete`。

### 权限范围

范围只有 `tasks:read` 与 `tasks:write`。业务上只读写清单「17项目日程」。其他清单不创建、不修改、不把其中的任务正文抄进仓库。

### 如何验证已连上

1. 在「17项目日程」建一条标题为「连接自检」的任务，截止为次日，正文第一行为 `opc-ref:connect-check`。
2. 17 在滴答该清单里能看到它。
3. 总助把该任务标为完成。
4. 17 能看到它已完成。即视为已连上。验证用的这行不要求在 Notion 留底，除非 17 希望保留。

### 失效重连

滴答令牌过期后，若刷新材料仍可用，总助只在环境变量里更新访问材料，不把材料写进仓库。刷新失败或滴答要求重新同意时，旧授权停止使用，必须由 17 本人重新打开授权页并同意。总助再做一次验证，并按 [日程](schedule.md) 用当前 Notion 对一遍清单。

## GitHub

### 前提

目标代码在 GitHub 仓库。17 指定仓库地址。云端开发 agent 或 17 本人对该仓库有开分支和开 PR 的权限。本仓库不存放 GitHub 登录材料。

### 步骤

1. 总助核对仓库地址、默认分支和 17 点名的目录。
2. 要动仓库时，才把开分支和提 PR 交给云端开发 agent。能在本地做的，按 [技能正文](../SKILL.md) 第 6 章优先交本地 Codex。
3. 从默认分支拉出新分支，分支名用 `feat/` 加项目简称和短描述。
4. 提交说明写清改了什么。提交内容不包含环境变量文件、证书和访问材料。
5. 用普通推送更新远程分支，然后打开 PR。PR 描述写范围和验证方式，附上自查需要的输出。
6. 把 PR 链接交回总助，由总助告诉 17。

### 权限范围

只操作 17 在当次任务里点名的仓库。不改仓库的密钥设置，不邀请新的协作者，不改默认分支保护。合并要等 17 写出「可以合并」。

### 如何验证已连上

打开云端开发 agent 提交的 PR 链接，能看到新分支、提交和与任务一致的说明。用仓库的文件视图确认被修改的文件属于该任务。PR 正文和 diff 里没有密钥值。

### 失效重连

推送或开 PR 时返回未授权，17 在 GitHub 上重新给云端开发 agent 授权，然后从同一条交接单重试。新的登录材料经加密输入框提供，存为环境变量，不进仓库。

## 云端开发 agent

### 前提

只有要动仓库、电脑离线，或任务太大时才使用。云端开发 agent 按次计用量。预计用量大时，先由总助问 17，同意后再开工。GitHub 一节的授权已经可用。能用本地 Codex 做的，不在这里开工，规则见 [技能正文](../SKILL.md) 第 6 章。

### 步骤

1. 总助写交接单：从总助到开发者，阶段写实现，附件是已确认的方案和对应任务单，要对方做的事写明仓库、默认分支、验收和「用普通推送开 PR，先不要合并」。
2. 云端开发 agent 从默认分支创建分支，完成任务单里的产出，推送并开 PR。
3. agent 把 PR 链接和验证说明交回总助。
4. 总助核对 PR 与任务单一致后，再决定是否进入演示或请 17 看 PR。

### 权限范围

agent 只改任务单列出的仓库和范围。它不开无关仓库的 PR，不合并，不用强制参数推送。17 写出「可以合并」后，总助另发一条交接，才可以合并。

### 如何验证已连上

同一条任务能在 GitHub 上看到新 PR，且 PR 的分支不是默认分支。总助能打开 diff。这同时说明 GitHub 与云端开发 agent 都可用。

### 失效重连

agent 报无法访问 GitHub 时，按 GitHub 一节重新授权，然后新开一条云端任务执行同一张交接单。已经推送的分支继续使用，不另开重复 PR；若远程还没有分支，再创建。

## Codex

### 前提

能用本地 Codex 做的，优先交本地 Codex。17 已经为本地 Codex 付费，额度内优先用它。优先范围是：本地文件、本机软件、本机环境、脚本、小改动，以及需要反复改的文案、样式和小 bug。只有要动仓库、电脑离线，或任务太大时，才改用云端开发 agent。云端开发 agent 按次计用量。不确定时，先用便宜的方式试，也就是先交本地 Codex。预计用量大的任务，先报总助，由总助问 17。17 同意后再交给云端开发 agent。权威描述在 [技能正文](../SKILL.md) 第 6 章。

执行时电脑在线。执行环境是 PowerShell。`codex` 不在 `PATH` 里，调用使用 `codex.exe` 的绝对路径。桌面应用若正占用某个会话，自动化另开新的 `codex exec`，不恢复那条会话。

### 步骤

1. 总助请 17 在本机 PowerShell 执行 `hostname`。17 把输出发回，视为电脑在线。没有输出则停止，不派本地任务。
2. 第一次使用或 17 说重装过时，在 PowerShell 解析绝对路径，只取第一条结果：

```powershell
Get-ChildItem -Path $env:LOCALAPPDATA -Filter codex.exe -Recurse -ErrorAction SilentlyContinue |
  Select-Object -First 1 -ExpandProperty FullName
```

3. 绝对路径记在总助运行备忘，不写入仓库。路径里常有系统用户名。
4. 总助把将要执行的这一条命令全文发给 17。命令形如：`& "<绝对路径>" exec "<这一条任务说明>"`。任务说明只含当次任务单。
5. 17 回复「批准执行」后，在新的 PowerShell 里执行。「一条命令一次批准」待 17 确认。确认前，不把「下一条必须重新批准」写成已经生效的制度。
6. 每次都是新的 `codex exec`。桌面应用正在使用的会话保持原样。不使用 `codex resume`，不使用 `codex exec --last`，不使用 `--resume-session-id`，不使用 `--resume-rollout`。
7. 执行结束后，总助把产出摘要交回 17，并写入项目档案。

### 权限范围

「一条命令一次批准」待 17 确认。在 17 确认前，只在 17 点名的本地项目目录里工作，执行前把命令全文发给 17。不读取项目以外的个人目录来写入仓库。

### 如何验证已连上

17 批准一条只读命令：`& "<绝对路径>" exec "列出当前项目顶层目录里的文件名"`。返回的文件名与 17 在资源管理器里看到的一致，即视为已连上。这条验证不恢复旧会话。

### 失效重连

电脑没有回应时，停止本地 Codex，告诉 17。电脑离线时，若任务是要动仓库或任务太大，并且不依赖本机才能做，才改派云端开发 agent，交接单写明改派原因；预计用量大时先由总助问 17。若任务是本地文件、软件、环境或脚本，等电脑在线后从第 1 步重做。

命令找不到程序时，重新解析绝对路径，请 17 再次批准新的命令全文。若解析结果为空，请 17 在资源管理器中确认安装位置，把绝对路径发回总助，总助核对文件名是 `codex.exe` 后再写入运行备忘。

若一条命令误入了桌面应用正在使用的会话，总助立即停止后续命令，告诉 17，下一次改为新的 `codex exec`，并请 17 在桌面应用里确认原会话仍由自己控制。

## ClawBot 微信桥

### 前提

17 与总助之间的微信已经通过 ClawBot/iLink 桥接通。桥是第三方通道。Grok Bot 主窗口是同一位总助的另一入口，桥不可用时改走主窗口。

### 步骤

1. 17 在已绑定的微信对话里发消息。
2. 桥把消息送到 Grok Bot 的总助。
3. 总助的回复经桥回到原微信对话。
4. 主窗口里 17 直接对总助说话，回复留在主窗口。两个入口的指示按到达时间排列。短时间互相冲突时，总助先停下，把两句话并列请 17 指定以哪一句为准。

### 权限范围

桥只传递 17 与总助之间的消息。总助不经桥向其他人发消息。对外发送仍要先得到「同意发送」，见 [规则](rules.md)。桥的登录态不写入仓库。

### 如何验证已连上

17 在微信发送「连接自检」。总助在 Grok Bot 里看到这句话，并回复「已收到连接自检」。同一句回复出现在微信里，即视为桥已连上。

### 失效重连

微信没有收到回复，或桥提示掉线时，以 Grok Bot 主窗口兜底：总助请 17 改到主窗口继续同一件事，主窗口里的确认同样有效。重新连接由 17 按桥提供方的登录流程完成。总助不索取微信口令。桥恢复后重做「连接自检」。掉线期间写在主窗口的决定，不自动转发到微信；17 要求同步时，总助再发一条摘要。
